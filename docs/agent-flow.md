# Agent 业务处理流程图

这份文档说明员工在服务台输入问题后，Agent 如何判断问题类型、进入哪条业务流程、会执行哪些操作，以及什么情况下只回复、追问、建单或转人工。

## 1. 整体处理流程

```mermaid
flowchart TD
  A[员工输入问题] --> B[页面先展示员工刚发送的内容]
  B --> C[系统接收本次咨询]
  C --> D{基础检查}

  D -- 内容为空/太长/员工身份异常 --> D1[提示员工重新输入或切换身份]
  D -- 检查通过 --> E[读取员工档案]

  E --> F{能否找到员工档案}
  F -- 找不到 --> F1[提示找不到员工信息]
  F -- 找到 --> G[进入 Agent 判断]

  G --> H{是否属于企业服务台范围}
  H -- 闲聊/打招呼/谢谢 --> H1[轻量回复<br/>不查制度、不建单、不转人工]
  H -- 天气/写代码/新闻/生活推荐等 --> H2[说明不在服务范围<br/>引导员工问 IT/HR/财务/行政问题]
  H -- 属于 IT/HR/财务/行政 --> I[理解员工诉求]

  I --> J{一句话是否包含多个事项}
  J -- 包含多个事项 --> J1[拆成多个事项<br/>例如 VPN 故障 + Figma 权限申请]
  J -- 只有一个事项 --> J2[按单事项处理]

  J1 --> K[每个事项分别走对应业务流程]
  J2 --> K

  K --> L[汇总所有事项的处理结果]
  L --> M[生成员工可读回复]
  M --> N[记录处理日志<br/>用于后台追溯和统计]
  N --> O[页面展示结果、依据、工单号或人工确认任务]
```

说明：

- “页面先展示员工刚发送的内容”不是意图识别，只是聊天界面把员工的话显示出来。
- 真正的意图识别发生在“理解员工诉求”这一步。
- “基础检查”不是审批，只是检查输入是否能被系统正常处理。

## 2. 员工问题如何分流

```mermaid
flowchart TD
  A[员工问题] --> B{问题类型}

  B -- 闲聊/无实义输入 --> C[直接回复<br/>例如：你好、谢谢、在吗]
  B -- 域外请求 --> D[说明服务范围<br/>例如：天气、写代码、股票、午饭推荐]
  B -- IT 支持 --> E{IT 具体事项}
  B -- HR 人事 --> F{HR 具体事项}
  B -- 财务 --> G{财务具体事项}
  B -- 行政 --> H{行政具体事项}
  B -- 无法识别但像公司事务 --> I[兜底转人工<br/>同时记录知识缺口]

  E -- 密码重置/账号解锁 --> E1[自助服务流程]
  E -- VPN/软件授权/普通权限 --> E2[权限申请流程]
  E -- 电脑/打印机/设备故障 --> E3[故障报修流程]
  E -- 生产库/root/批量导出/堡垒机 --> E4[高危权限流程]

  F -- 年假/社保/入职/转正制度咨询 --> F1[HR 制度问答流程]
  F -- 请假/调休申请 --> F2[HR 事务办理流程]
  F -- 薪酬/绩效/离职/劳动争议 --> F3[HR 敏感事项流程]

  G -- 报销标准/发票/开票 --> G1[财务制度问答流程]
  G -- 提交报销 --> G2[报销办理流程]
  G -- 预算外支出/付款/对公转账 --> G3[大额资金流程]

  H -- 门禁/会议室/办公用品/出差订票/工位 --> H1[行政服务流程]
```

## 3. 单个事项的标准处理流程

```mermaid
flowchart TD
  A[一个已识别的事项] --> B[匹配对应处理套路<br/>服务类型、默认动作、负责团队]
  B --> C[提取关键信息<br/>金额、天数、日期、系统名、软件名等]

  C --> D{办理必填信息是否齐全}
  D -- 不齐全 --> D1[先追问员工补充信息<br/>不提前建错单]
  D -- 齐全 --> E[检索企业制度和知识库]

  E --> F{是否找到可靠制度依据}
  F -- 找到 --> F1[把制度条款作为回答依据]
  F -- 找不到 --> F2[记录知识缺口<br/>后续给知识运营补充]

  F1 --> G[按需要查询员工信息或权限状态]
  F2 --> G

  G --> H[风险分级]
  H --> I{处理方式}

  I -- 低风险 --> I1[直接回答员工]
  I -- 中风险 --> I2[回答员工 + 创建工单]
  I -- 高风险 --> I3[回答员工 + 创建工单 + 创建人工确认任务 + 转人工]
  I -- 信息缺失 --> I4[追问员工补充信息]
  I -- 没有可靠依据 --> I5[不编答案 + 记录知识缺口 + 转人工]

  I1 --> J[返回处理结果]
  I2 --> J
  I3 --> J
  I4 --> J
  I5 --> J
```

## 4. 具体问题进入什么流程

| 员工问题类型 | 典型说法 | 进入流程 | Agent 会做什么 | 员工会看到什么 |
| --- | --- | --- | --- | --- |
| 闲聊/打招呼 | “你好”“在吗”“谢谢” | 闲聊拦截 | 直接轻量回复，不查知识库，不建单 | 服务台能力说明或简单回应 |
| 域外请求 | “今天天气怎么样”“帮我写代码”“午饭吃什么” | 域外拦截 | 说明这不是企业服务台范围，不记录知识缺口 | 告诉员工可咨询 IT/HR/财务/行政事项 |
| 账号密码 | “OA 密码忘了”“邮箱登不上” | IT 自助服务 | 查 IT 知识库，必要时结合员工信息 | 给重置/解锁步骤，不默认建单 |
| VPN 或普通权限 | “帮我开通 VPN”“申请 Figma 编辑权限” | IT 权限申请 | 提取系统或软件名，查权限状态，查制度，创建权限申请工单 | 权限规则说明 + 工单号 + 预计响应时间 |
| 软件授权但缺软件名 | “帮我申请一个软件授权” | 信息补全 | 发现缺少“软件名称” | 追问员工要申请哪个软件 |
| 设备故障 | “电脑蓝屏”“打印机坏了”“笔记本开不了机” | IT 故障报修 | 查故障处理知识，创建报修工单 | 自查建议 + 报修工单号 |
| 生产数据/高权限 | “开生产库权限”“给我 root”“导出全部客户名单” | 高危权限 | 查制度和现有权限，创建工单，创建人工确认任务，转安全与合规组 | 明确说明不能直接开通 + 人工确认编号 |
| 年假/社保/转正咨询 | “年假还剩几天”“社保怎么转”“转正流程是什么” | HR 制度问答 | 查 HR 制度，读取员工档案中可用事实 | 结合员工档案和制度依据回答 |
| 请假/调休申请 | “帮我请 3 天年假，从下周一开始” | HR 事务办理 | 提取假期类型、开始日期、天数；查制度；创建事务工单 | 已受理说明 + 工单号 + 审批人 |
| 请假信息不全 | “我想请假” | 信息补全 | 发现缺少假期类型、开始日期、天数 | 追问员工补齐关键信息 |
| 长假申请 | “我要请 12 天年假” | 高风险 HR 事务 | 因连续请假天数较长，升级人工确认 | 工单 + 人工确认，提示需上级和 HR 确认 |
| 薪酬/绩效/离职 | “我想调薪”“为什么工资少了”“我要离职” | HR 敏感事项 | 不在聊天里展开细节，创建人工确认任务，转 HRBP | 告知 HRBP 会一对一跟进 |
| 报销标准 | “成都住宿能报多少”“打车费能报吗” | 财务制度问答 | 查财务制度，引用金额标准和适用条件 | 报销规则 + 制度依据 |
| 提交报销 | “帮我报销 1200 元差旅费” | 报销办理 | 提取金额和费用类别，查制度，创建报销工单 | 报销工单号 + 后续贴票/交单提醒 |
| 报销缺金额 | “帮我提交一笔报销” | 信息补全 | 发现缺少报销金额 | 追问员工补充金额 |
| 大额报销 | “帮我报销 8600 元” | 高风险财务办理 | 因金额超过自动通道上限，创建工单和人工确认任务 | 告知需财务复核，不直接自动通过 |
| 预算/付款 | “有一笔 8 万预算外付款要审批” | 大额资金流程 | 提取金额，查制度，创建工单和人工确认任务，转财务负责人 | 明确不会自动提交资金动作 + 人工确认编号 |
| 发票/开票 | “公司开票信息是什么”“专票怎么开” | 财务制度问答 | 查发票制度或开票信息 | 给开票要求、抬头/税号相关说明 |
| 行政服务 | “会议室怎么订”“工牌丢了”“想领打印纸”“下周出差怎么订票” | 行政服务 | 查行政制度，说明地点、负责人、时限、材料要求 | 给办理路径和注意事项 |
| 公司事务但无法匹配 | “带样机去德国参展的清关手续怎么办” | 兜底转人工 | 查不到可靠制度时记录知识缺口，创建工单，转服务台值班 | 不编答案，给工单号，说明人工跟进 |

## 5. 四类业务流程展开

### IT 流程

```mermaid
flowchart TD
  A[IT 类问题] --> B{具体类型}

  B -- 密码/账号解锁 --> C[查账号自助处理知识]
  C --> C1[给员工自助步骤]
  C1 --> C2[默认不建单<br/>解决不了可再转人工]

  B -- VPN/软件/普通权限 --> D[提取系统或软件名]
  D --> D1{关键信息是否齐全}
  D1 -- 否 --> D2[追问系统名或软件名]
  D1 -- 是 --> D3[查权限状态 + 查制度]
  D3 --> D4[创建权限申请工单]

  B -- 设备故障 --> E[查故障处理知识]
  E --> E1[给自查建议]
  E1 --> E2[创建报修工单]

  B -- 生产环境/高权限/批量数据 --> F[标记高风险]
  F --> F1[查制度和权限状态]
  F1 --> F2[创建工单]
  F2 --> F3[创建人工确认任务]
  F3 --> F4[转安全与合规组]
```

### HR 流程

```mermaid
flowchart TD
  A[HR 类问题] --> B{具体类型}

  B -- 年假/社保/入职转正咨询 --> C[查 HR 制度]
  C --> C1[读取员工档案中的可用事实]
  C1 --> C2[结合个人情况回答]

  B -- 请假/调休申请 --> D[提取假期类型、开始日期、天数]
  D --> D1{信息是否齐全}
  D1 -- 否 --> D2[追问缺失信息]
  D1 -- 是 --> D3[查假期制度]
  D3 --> D4{是否长假或特殊风险}
  D4 -- 否 --> D5[创建 HR 事务工单]
  D4 -- 是 --> D6[创建工单 + 人工确认任务]

  B -- 薪酬/绩效/离职/劳动争议 --> E[标记敏感事项]
  E --> E1[不在聊天中展开细节]
  E1 --> E2[创建工单和人工确认任务]
  E2 --> E3[转 HRBP 一对一处理]
```

### 财务流程

```mermaid
flowchart TD
  A[财务类问题] --> B{具体类型}

  B -- 报销标准/发票/开票 --> C[查财务制度]
  C --> C1[给出标准、上限、材料要求]

  B -- 提交报销 --> D[提取金额和费用类别]
  D --> D1{是否有金额}
  D1 -- 否 --> D2[追问报销金额]
  D1 -- 是 --> D3[查报销制度]
  D3 --> D4{金额是否达到人工复核线}
  D4 -- 否 --> D5[创建报销工单]
  D4 -- 是 --> D6[创建报销工单 + 人工确认任务]

  B -- 预算/付款/对公转账 --> E[标记资金高风险]
  E --> E1[提取金额和事由]
  E1 --> E2[查付款审批制度]
  E2 --> E3[创建工单 + 人工确认任务]
  E3 --> E4[转财务负责人复核]
```

### 行政流程

```mermaid
flowchart TD
  A[行政类问题] --> B{具体类型}

  B -- 门禁/工牌 --> C[查门禁和工牌制度]
  B -- 会议室/场地 --> D[查预定规则<br/>可提取日期和人数]
  B -- 办公用品 --> E[查领用规则<br/>可提取物品]
  B -- 出差/订票 --> F[查出差订票规则<br/>可提取城市和日期]
  B -- 工位/搬迁 --> G[查工位调整规则]

  C --> H[给办理地点、负责人、材料、时限]
  D --> H
  E --> H
  F --> H
  G --> H

  H --> I{知识库是否有依据}
  I -- 有 --> I1[直接答复]
  I -- 没有 --> I2[记录知识缺口 + 创建工单 + 转人工]
```

## 6. 风险等级决定会不会自动办理

```mermaid
flowchart LR
  A[低风险] --> A1[只回答<br/>适合制度咨询、自助说明]
  B[中风险] --> B1[回答 + 建工单<br/>适合常规办理和故障处理]
  C[高风险] --> C1[回答 + 建工单 + 人工确认<br/>适合权限、资金、生产数据、人事敏感]
  D[信息缺失] --> D1[先追问<br/>不提前建单]
  E[知识无依据] --> E1[不编答案<br/>记录知识缺口并转人工]
```

当前风险升级规则的业务含义：

| 触发情况 | 处理结果 |
| --- | --- |
| 出现生产环境、生产库、root、管理员权限、堡垒机等词 | 直接按高风险处理 |
| 出现批量导出、全量数据、客户名单等词 | 直接按高风险处理 |
| 薪酬、绩效、离职、裁员、劳动争议 | 转 HRBP 或相关人工团队 |
| 报销金额达到 5000 元及以上 | 升级为财务人工复核 |
| 单笔金额达到 50000 元及以上 | 触发大额兜底，高风险 |
| 连续请假达到 10 天及以上 | 需要上级和 HR 双重确认 |
| 试用期员工申请权限 | 风险等级上调一级 |
| 知识库没有可靠依据 | 不自动答复，至少转人工 |
| 关键信息缺失 | 强制追问，不先建单 |

## 7. 一个完整例子

员工输入：

> VPN 连不上，顺便帮我申请 Figma 编辑权限。

处理过程：

```mermaid
flowchart TD
  A[员工输入一句话] --> B[识别为两个事项]
  B --> C[事项 1：VPN 连不上]
  B --> D[事项 2：申请 Figma 编辑权限]

  C --> C1[进入 IT 权限/远程访问流程]
  C1 --> C2[查 VPN 制度和当前权限状态]
  C2 --> C3[生成处理建议]
  C3 --> C4[按风险创建工单或提示后续处理]

  D --> D1[进入软件授权流程]
  D1 --> D2[提取软件名：Figma]
  D2 --> D3[查授权规则和当前权限状态]
  D3 --> D4[创建权限申请工单]

  C4 --> E[汇总两个事项]
  D4 --> E
  E --> F[员工看到两个处理结果和对应工单信息]
```

最终员工看到的不是一段泛泛回答，而是分事项的结果：

- VPN 相关处理依据是什么。
- Figma 权限是否已提交申请。
- 哪些事项已经生成工单。
- 如果风险较高，哪些事项需要人工确认。

## 8. 这套设计的产品价值

| 设计点 | 解决的问题 |
| --- | --- |
| 先判断服务范围 | 避免天气、写代码、午饭推荐这类问题污染工单和知识缺口 |
| 多事项拆分 | 员工一句话可以同时问多个事，不需要拆开重问 |
| 必填信息追问 | 缺金额、缺日期、缺软件名时不乱建单 |
| 制度依据优先 | 员工得到的不是“模型猜测”，而是可追溯的制度答案 |
| 风险分级 | 低风险自动答，高风险不自动执行 |
| 人工确认任务 | 高风险事项给人工准备好证据、员工信息、制度依据和建议动作 |
| 知识缺口沉淀 | 答不上来的问题不会消失，会进入后台知识运营 |
