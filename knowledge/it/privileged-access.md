## 原则

1. **最小权限**：只授予完成当前任务所必需的最小权限范围与最短时长。
2. **人工审批不可绕过**：任何自动化系统（含智能服务台）都不得自动授予特权访问。
3. **全程留痕**：特权会话全程录屏留存 180 天。

## 需要走特权审批的访问类型

- 生产数据库读权限、写权限、DDL 权限
- 生产服务器 SSH / root / sudo
- 配置中心、密钥管理系统的写权限
- 单次超过 1000 条的客户数据导出
- 涉及个人敏感信息（身份证、手机号、银行卡）的任何导出

## 审批链路

| 权限类型 | 审批链路 | 最长有效期 |
| --- | --- | --- |
| 生产库只读 | 直属上级 → 数据Owner → 安全与合规组 | 7 天 |
| 生产库写 / DDL | 直属上级 → 数据Owner → 安全负责人 → CTO | 24 小时（随变更单） |
| 生产服务器 sudo | 直属上级 → SRE 负责人 → 安全负责人 | 8 小时 |
| 客户数据批量导出 | 直属上级 → 数据Owner → 法务合规 → 安全负责人 | 单次一批 |

## 申请材料

必须提供：目标系统、环境、具体数据范围、业务理由、预计时长、是否可用脱敏数据替代。业务理由不接受「排查问题」这类笼统描述，需说明具体工单号或需求编号。

## 替代方案（优先推荐）

- 数据分析场景：使用数仓脱敏视图，T+1 数据，无需特权审批
- 线上问题排查：通过 APM / 日志平台查询，覆盖 90% 排查场景
- 数据修正：提交数据变更单由 DBA 执行，不下放直接写权限

## 违规处理

绕过审批获取或使用特权访问，按《信息安全奖惩办法》处理，情节严重者解除劳动合同并追究法律责任。
