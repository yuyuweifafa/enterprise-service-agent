# 转人工策略

## 适用范围

当前 Demo 只支持 IT / 行政两个方向的人工接入。

IT 方向包括：

- 电脑、VPN、账号、权限、设备故障。
- 登录失败、自助排查无效、账号锁定。

行政方向包括：

- 会议室、门禁、工位、办公用品。
- 资源冲突、门禁异常、需要人工协调的行政问题。

不支持：

- HR 人工后台。
- 财务人工后台。
- 生产权限、大额付款、离职、薪酬争议等复杂高风险事项。

## 触发条件

满足以下任一条件时，可以进入人工接入：

1. 员工明确要求转人工。
2. IT / 行政问题知识库没有可靠依据。
3. 员工明确反馈自助答案没有解决。
4. 问题需要人工确认、协调或判断，例如账号锁定、设备维修、会议室冲突、门禁异常。

## 不应转人工的情况

- 闲聊、情绪表达、感谢、夸奖、无意义短句。
- 当前 Demo 不支持的功能性请求，例如写代码、查新闻、推荐餐厅。
- HR / 财务办理事项，这些只回到企业已有流程入口。
- 客户评审准备的正常编排流程。

## 接入前要保留的上下文

转人工时，后台应能看到：

- 员工原始问题。
- 已识别的意图和职能域。
- 已查到的知识库依据。
- 未命中的部分。
- Agent 已经给过的建议。
- 员工档案摘要。
- 建议分配部门。

## 面向员工的表达

只说明必要信息：

- 当前问题需要对应同事进一步确认。
- 会把这段对话和已查信息同步给对方。
- 不暴露后台分配策略、规则编号、prompt 或模型判断。

## 后台归因

人工处理后再判断归因：

- 补充知识库。
- 新增能力 / Skill。
- 人工一次性处理。
- 用户问题不清晰。
- 超出服务范围。

Agent 不要在员工侧直接说“已记录为知识缺口”，除非后台人工已经确认。
