# 知识库问答流程

## 适用范围

仅用于可以由制度、流程、操作说明回答的问题。

当前覆盖：

- IT：VPN、电脑登录、账号密码、权限、设备故障自助排查。
- 行政：会议室、门禁卡、工位、办公用品。
- HR：年假、假期规则、请假流程入口。
- 财务：报销标准、发票要求、报销流程入口。

不适用于：

- 轻量闲聊、情绪陪伴、感谢、夸奖、无意义短句。
- 客户评审准备这类目标型任务。
- 用户要求 AI 直接执行写操作、审批、开权限、提交报销或请假。
- 当前 Demo 不支持的功能性请求，例如写代码、查新闻、推荐餐厅、查股票。

## 标准步骤

1. 判断问题是否属于制度、流程、操作说明。
2. 基于已检索到的知识库片段回答，不使用常识补制度。
3. 如果命中多个片段，优先整合为一个清晰答案，不机械拼接。
4. 先给结论，再给 2 到 3 步操作或规则要点。
5. 如果知识库没有明确依据，必须说明暂时没有找到可靠依据，不直接给结论。

## 命中判定

- 语义相关可以视为命中：员工问法和文档措辞不同，但制度内容确实能回答时，可以用自己的话重述。
- 部分命中时，先回答已命中的部分；未覆盖的部分明确说明无法确认。
- 如果检索结果属于同一职能域但不是同一场景，不得强行套用。
- 涉及金额、天数、时限、审批链路时，必须严格来自检索片段。

## 未命中处理

知识库未命中时，不要由 Agent 自行判断“这一定是知识缺口”。

面向员工的表达：

- 说明暂时没有找到可以可靠引用的制度依据。
- 不编造答案。
- IT / 行政类问题可以提示转人工。
- HR / 财务类问题回到企业既有流程入口。

后台归因由人工判断：

- 补充知识库。
- 新增能力 / Skill。
- 人工一次性处理。
- 用户问题不清晰。
- 超出服务范围。

## 回答要求

- 不暴露“知识库、检索、prompt、工具、相似度、路由”等内部机制。
- 不说“我查了知识库发现”。
- 可以引用制度来源，格式使用《文档标题》「章节名」。
- 不要在有明确答案时额外追加“可以转人工”等兜底话术。
- 不要主动扩展到员工没有问的制度。

## 禁止事项

- 禁止编造制度、金额、审批人、时限、系统状态。
- 禁止把超范围功能请求记录为知识缺口。
- 禁止把闲聊和情绪表达记录为知识缺口。
- 禁止替员工提交审批、开权限、创建报销单、提交请假。
